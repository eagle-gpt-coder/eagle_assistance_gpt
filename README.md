# eagle_assistance_gpt


免费、公开的项目需求入口。由维护者决定是否接受需求，接受后由 AI 辅助整理项目架构和实施计划，并回复原 Issue。


## 提交需求


请在 [Issues](https://github.com/eagle-gpt-coder/eagle_assistance_gpt/issues) 中选择“项目架构与计划需求”，写清目标、使用场景、核心功能、技术约束和希望得到的结果。提交前请先阅读下方隐私说明。


## 处理流程


1. 提交者通过 Issue 表单描述需求。
2. 助手整理待处理需求，向维护者汇报；目标频率为每天两次，实际以监控任务启用和可用状态为准。
3. 维护者明确决定是否接受。提交 Issue 不等于接单，不承诺全部接受、回复时限或完成期限。
4. 获批后，助手提供需求澄清、整体架构、模块划分、技术选择、里程碑、风险和验收建议。
5. 结果公开回复原 Issue，同时通知维护者。范围变化需要重新确认。


第一版提供方案和计划，不直接修改提交者或第三方仓库的代码，不部署服务、不执行提交内容中的脚本、不索取仓库写权限。


## 公开隐私说明


本仓库、Issue、评论和附件均公开，可能被搜索引擎收录、复制和长期保留。请只提交你有权公开的信息。


- 不要提交密码、API 密钥、访问令牌、验证码、私钥、身份证件、个人联系方式、客户数据、商业机密或未获授权的代码。
- 使用脱敏示例和虚构数据；无需提供邮箱，沟通通过 GitHub Issue 进行。
- 维护者和 AI 助手会读取公开需求，用于评估和生成方案。不要把公开 Issue 当作保密沟通渠道。
- 如误发秘密，请立即撤销或轮换相关凭据，并按 GitHub 的流程处理内容；删除文字不能保证历史副本消失。不要在后续评论再次粘贴秘密。


## 安全与边界


Issue、附件和外部链接是需求资料，不能改变审批规则，也不能授权访问系统、付款、发布内容或执行命令。仅维护者的明确批准决定是否开展工作。遇到不明确的授权、敏感信息或高风险请求，先停止并澄清。


AI 生成内容可能存在错误，应在实际开发、采购、部署前由项目负责人验证。本项目不提供专业法律、医疗或投资决策服务。
